# Spec: Filter the vendor without replacing Blizzard's merchant API
Intent: [intent.md](intent.md). Status: accepted

"22.2" below means the current build (`main` at `d0e8771`), the baseline every "as today" is measured against.

## Phases
- **Phase 1**: the redesign, with the CanIMogIt and ElvUI plugins (requirements 1-17).
- **Phase 2**: plugins for GW2_UI's merchant skin and EllesmereUI's merchant skin and item levels (requirements 18-20), built on phase 1's public plugin methods.
- One release carries both phases; no release in between. Each phase is its own pull request into `main`.
- Plumber's merchant prices are not in either phase: Plumber's price display is private to Plumber, so how to serve it is decided separately, before the release.

## Requirements
Players with only Extended Vendor UI, on every client:
1. The merchant tab shows the same items in the same slots and order as 22.2, for every Rows, Columns and Direction setting and every filter, Custom, Hide collected and search setting.
2. Each slot looks as in 22.2: name, icon, stack count, stock, money or alternate-currency cost and their anchors, grey money when unaffordable, the red or grey tint for unusable, sold-out or known heirloom items, the quest icon (Retail) and the quality colour (Retail).
3. Paging looks and works as in 22.2: previous and next buttons and page text in the same place and style (Retail "Page x of y", Classic "Page x"), shown only when the filtered list fills more than one page, disabled on the first and last page; the mouse wheel over the window pages; the page goes back to 1 when a vendor opens and on any filter or search change; the window is as tall as in 22.2 with and without the page controls.
4. On a slot, the tooltip and comparison tooltip, the buy and cannot-afford cursors, left-click pick-up, right-click buy, dragging to a bag, a character slot or the window, shift-click (split window, or Bulk Purchase when on), ctrl-click dress-up, shift-click chat link and the alternate-currency cost tooltips all act on the item the slot shows.
5. Every purchase confirmation 22.2 shows still shows for the same item and quantity: extended cost, non-refundable, high price (150 gold or more), limited currency (Retail), also after dragging the item to a bag or a character slot.
6. The buyback tab, the last-sold slot, the repair, guild repair and sell-junk buttons, the filter button, search box, options button and token banner look and sit as in 22.2.
7. The filter menu lists the same entries per client; RememberFilter, RememberSearch and RememberSearchBetweenVendors behave as in 22.2; `KrowiEVU_Filters.LastFilter` is written whenever 22.2 writes it.
8. The token banner totals the items the filter shows.
9. Changing Direction, Rows, Columns or Housing Quantity from the options button updates the open window at once; slots added this way work, are skinned and carry CanIMogIt icons without `/reload`.
10. Bulk Purchase opens for, and buys, the shift-clicked item.
11. Krowi_Vendorer's Ignore List and Junk List tabs show no item slots: `KrowiEVU_MerchantItemsContainer:HideAll()` hides the grid and Blizzard's `MerchantItem1-12`, as in 22.2.

The only intended differences for those players:

12. Retail: the non-refundable prompt checks the clicked item under a filter. Classic: the token banner's gold total matches the shown items under a filter. With Bulk Purchase on, a shift-click with chat open links once and a ctrl-click dresses up once, on both tabs. Retail under the `MerchantFilterDisabled` game rule: the grid updates. Classic: Bulk Purchase reads `isPurchasable` and `hasExtendedCost` from the right return values.

Taint:

13. No Extended Vendor UI file assigns a Blizzard global, a field of a `C_*` table, a Blizzard `StaticPopupDialogs` entry or a field of a Blizzard frame, and none calls `MerchantFrame_Update`, `MerchantFrame_UpdateMerchantInfo` or another Blizzard refresh function. Hooks on Blizzard code are `hooksecurefunc` and `HookScript` only.
14. Blizzard's merchant code (opening a vendor, its events, the hover cursor, other addons' API calls) runs no Extended Vendor UI code other than those post-hooks.

Other addons:

15. Every merchant API returns the vendor's real list to other addons whatever the filter, and `GameTooltip:SetMerchantItem` gets the real index (Auctionator's tooltip prices match the hovered item).
16. CanIMogIt: an icon on every merchant-tab slot in CanIMogIt's configured position, as in 22.2; refreshed after every grid update (vendor open, merchant update, page, filter, search and option change) and on slots added this session. Nothing happens when CanIMogIt or the functions the plugin uses are missing.
17. ElvUI with its merchant skin on (v16, the current release, one merchant skin for every client: `ElvUI/Game/Shared/Skins/Merchant.lua`): every slot and both page buttons look as in 22.2, which is this addon's own ElvUI slot skin with ElvUI's on top, prices placed as ElvUI places them and, on the Classic clients, names and borders in quality colours on every filled slot. Slots added this session look the same without `/reload`. (Corrected 2026-10-19: the per-client ElvUI skins first read for this spec, which coloured only slots 1-12, were replaced by v16 on Krowi's clients; v16 already reached every slot through `MERCHANT_ITEMS_PER_PAGE`, so this is no improvement over 22.2, only no loss.)

Phase 2:

18. GW2_UI with its merchant skin on, on every client it supports (Retail, Mists, Anniversary, Era): every slot carries GW2_UI's slot skin as in 22.2, where GW2_UI skins the `MerchantItemN` frames Extended Vendor UI creates; prices sit where GW2_UI places them; on Mists, names and borders are coloured by quality as GW2_UI does there. Slots added this session are skinned too.
19. EllesmereUI with its merchant window skin on in grid mode (Retail): every slot looks like EllesmereUI's merchant tile in 22.2 (dark card fill, border, faded slot art, square rarity border on the icon, icon centred in the row, names on up to two lines), on every slot (22.2: slots 1-12 only), and follows EllesmereUI's skin style setting.
20. EllesmereUI's merchant item levels on (Retail): weapon and armour slots show their item level top left in EllesmereUI's font and colour, on every slot (22.2: slots 1-12 only), refreshed with the grid and when the option is toggled.

## Root cause
This is a redesign, not a single bug; the mechanism behind the known debt (`CLAUDE.md`, Known debt):
- `Gui/MerchantFrame.lua:180-237` replace `CanAffordMerchantItem`, `GetMerchantItemLink`, `GetMerchantItemID`, `GetMerchantItemCostInfo`, `GetMerchantItemCostItem`, `GetMerchantNumItems`, `BuyMerchantItem`, `PickupMerchantItem` and `GetMerchantItemMaxStack`; `:156-178` add `GetMerchantItemInfo` and write `C_MerchantFrame.GetItemInfo` on Classic, `:264-268` replace it on Retail; `:239-244` wrap `MerchantFrame_GetProductInfo`; `:246-262` replace the purchase popups' `OnAccept`; `Gui/MerchantItemsContainer.lua:91` writes `MERCHANT_ITEMS_PER_PAGE`. Blizzard's `MerchantFrame_UpdateMerchantInfo` (live `MerchantFrame.lua:267-468`, classic TBC `MerchantFrame.lua:187-387`) then pages through `addon.CachedItemIndices`, and every caller of those globals, Blizzard's or another addon's, gets a filtered position instead of the vendor's index.
- The grid reuses Blizzard's `MerchantItem1-12` and creates `MerchantItem13+` from `MerchantItemTemplate` (`Gui/MerchantItemsContainer.lua:58-79`), replaces their `OnEnter` and hooks their `OnClick` (`:17-56`), and on Classic replaces `MerchantFrame_Update` (`:115-119`).
- The filter lives in the C merchant filter on Retail and in Blizzard-named globals on Classic (`Filters.lua:105-114`); every change goes through the addon's global `MerchantFrame_SetFilter` (`Krowi_ExtendedVendorUI.lua:45-51`), which writes `MerchantFrame.page` and calls `MerchantFrame_Update()`. `Gui/OptionsButton/OptionsButtonMixin.lua:9-13` also calls `MerchantFrame_Update()`.
- `Plugins/CanIMogIt.lua:14` tests for `MerchantFrame_CIMIOnClick`, which the installed CanIMogIt does not define (its merchant refresh is `CIMI_UpdateMerchantFrame`, `CanIMogIt/Overlay/Merchant.lua:51`). `Plugins/ElvUI.lua:159-162` skins the slots once and then replaces its own skin function with a no-op, so slots added later stay unskinned; `:151-153` writes a `PointXY` no-op onto `MerchantItem1-12` to stop ElvUI's Classic `MerchantItemPoint` (`ElvUI/Game/Mists/Modules/Skins/Merchant.lua:13-23`) from moving the grid.

## Design
Extended Vendor UI keeps its own list of the vendor indices that pass the filter, and shows them in its own item slots with its own paging. Blizzard's merchant code runs untouched underneath: it still fills its own `MerchantItem1-10` and page widgets, which the addon hides on the merchant tab. Purchases, tooltips, confirmations and stack splitting stay Blizzard's code, run on the addon's slots with the vendor's real index.

**Filter state** (`Filters.lua`)
- `filters:GetFilter()` and `filters:SetFilter(id)` hold the active filter in a file local. On Retail `SetFilter` also calls the real `SetMerchantFilter(id)` with the same value 22.2 passes (custom ids 101-201 included), so the server returns the same list as today by construction. `SetFilter` writes `KrowiEVU_Filters.LastFilter` (as `FilterButtonMixin.lua:259-265` does now) and notifies its listeners: the filter button's text, the search box (clear on a non-search filter, as `SearchBoxMixin.lua:39-46`), the grid (page 1, rebuild, draw) and the token banner.
- Vendor open: on Retail the existing `ResetSetMerchantFilter` post-hook sets the filter to `LastFilter` when RememberFilter is on, otherwise reads back Blizzard's reset value with `GetMerchantFilter()`; on Classic the existing `OnShow` hook sets `LastFilter` or `LE_LOOT_FILTER_ALL` (`FilterButtonMixin.lua:267-283`). Neither calls a Blizzard refresh; Blizzard's own `MerchantFrame_OnShow` refreshes right after.
- `filters:BuildList(list)` is the loop now in `GetMerchantNumItems`'s wrapper (`Gui/MerchantFrame.lua:205-218`), moved unchanged: real indices `1..GetMerchantNumItems()` whose item id is nil or passes `Validate`.
- Replaces `MerchantFrame_SetFilter`, the Classic `GetMerchantFilter` and `SetMerchantFilter`, and the three `hooksecurefunc('MerchantFrame_SetFilter', ...)` (filter button, search box, CanIMogIt plugin).

**Item slots** (`Gui/MerchantItemsContainer.lua`, a new `Gui/MerchantItemsContainer.xml` listed before it in `Gui/Files.xml`)
- `KrowiEVU_MerchantItem_Template` inherits Blizzard's `MerchantItemTemplate` (each client's own: live `MerchantFrame.xml:3-90`, classic TBC and Vanilla equivalents). Slots are `KrowiEVU_MerchantItem<N>` on `MerchantFrame`, created on demand up to `NumRows * NumColumns`, so child names (`...ItemButton`, `...MoneyFrame`, `...AltCurrencyFrame`, `...Name`) follow Blizzard's `$parent` pattern.
- The item button keeps the template's `OnLoad`, `OnEnter`, `OnLeave`, `OnDragStart` and `OnHide`, so tooltips, cursors, `MerchantFrame.itemHover`, stack splitting and dragging are Blizzard's. Its `OnClick` is set by the addon on its own button: Bulk Purchase when it is on and the click qualifies, otherwise `MerchantItemButton_OnModifiedClick` or `MerchantItemButton_OnClick` exactly as Blizzard's XML (live `MerchantFrame.xml:43-49`). One call per click.
- Placement reuses `DrawItemSlots` (offsets and Direction unchanged).
- This keeps purchase safety Blizzard's: `MerchantItemButton_OnClick` (live `MerchantFrame.lua:632-669`) sets `MerchantFrame.extendedCost` and `MerchantFrame.highPrice`, which the bag and character-slot drop handlers read to show the confirmation (live `ContainerFrame.lua:1349-1356`, `PaperDollFrame.lua:1626-1629`), and `MerchantFrame_ConfirmExtendedItemCost` and `MerchantFrame_ConfirmHighCostItem` store the button's real `GetID()` for the popups' `OnAccept` (live `GameDialogDefs.lua:364-398, 484-501`, Mainline `GameDialogDefs.lua:35-50`).

**Drawing a slot**
- For slot `i` on page `p`, the real index is `list[(p - 1) * perPage + i]`. The slot is filled the way Blizzard's per-item block does, calling the real API with that index and ending with `ItemButton:SetID(index)`: Mainline mirrors live `MerchantFrame.lua:275-403`; one Classic variant mirrors classic TBC `MerchantFrame.lua:196-321` for Mists, Anniversary and Era (Era's Vanilla copy differs only in the heirloom check, which TBC's `ClassicExpansionAtLeast(LE_EXPANSION_WRATH_OF_THE_LICH_KING)` guard already turns off below Wrath). The source lines go in a comment so the copy can be compared after each patch.
- Alternate currency uses the addon's copy of `MerchantFrame_UpdateAltCurrency` (live `:470-504`), which builds frame names from `"MerchantItem"..indexOnPage` and cannot address the addon's slots; it calls Blizzard's `AltCurrencyFrame_Update` on the addon's frames.
- Quality (Retail) mirrors `MerchantFrameItem_UpdateQuality` (live `:212-228`) on the addon's slot, with an addon frame for `GET_ITEM_INFO_RECEIVED` while a merchant is open, instead of calling Blizzard's function, which registers the event on `MerchantFrame`. Classic shows no quality (TBC `:137-148` is empty), as today.
- On Classic a file-local helper returns the `MerchantItemInfo` shape from `GetMerchantItemInfo` (nothing written into `C_MerchantFrame`); drawing, the token banner and Bulk Purchase all use it.
- Drawing runs from the `MerchantFrame_UpdateMerchantInfo` post-hook (only when `MerchantFrame.selectedTab == 1`, which also covers Krowi_Vendorer calling it on its own tabs), and directly on filter, page and option changes. Every Blizzard refresh (vendor open, `MERCHANT_UPDATE`, `BAG_UPDATE`, currency, inventory, tab clicks) ends in that function, also under `MerchantFilterDisabled`, so the separate `FilterDropdown:Update` hook and the Classic `MerchantFrame_Update` replacement go (`MerchantItemsContainer.lua:110-120`).

**Paging**
- Own previous and next buttons from a template copying Blizzard's (the same on every client: live `MerchantFrame.xml:520-575`), and an own `GameFontNormal` page text, at the anchors 22.2 gives Blizzard's (`Gui/MerchantFrame.lua:49-54`). Text, visibility and enabled state follow Blizzard's rules (live `:431-450`, TBC `:351-370`) with the filtered count and `NumRows * NumColumns`; the click sound matches `MerchantPrevPageButton_OnClick`.
- Mouse wheel: `MerchantFrame:HookScript('OnMouseWheel', ...)` on the merchant tab. Blizzard's own wheel handler does nothing because its page buttons are hidden (live `:177-187`).
- A page change closes the split window when one of the addon's slots owns it (`MerchantFrame_CloseStackSplitFrame` only knows `MerchantItemN`, live `:587-597`). Hiding the grid on a tab change closes it through the template's `OnHide`.
- `SetMerchantFrameSize` (`Gui/MerchantFrame.lua:68-83`) reads the addon's page text instead of `MerchantPageText`.

**Blizzard's widgets**
- Merchant tab: the existing post-hook hides `MerchantItem1-10`, `MerchantPrevPageButton`, `MerchantNextPageButton` and `MerchantPageText` (method calls only, like the `FilterDropdown:Hide()` there today). Buyback tab: the grid hides, Blizzard's `MerchantItem1-12` show and are laid out as in 22.2 (`MerchantItemsContainer.lua:175-182`), with Blizzard's own `OnEnter` and `OnClick` (no override any more).
- `HideAll()` hides the grid, the addon's page widgets and `MerchantItem1-12`.

**Token banner and Bulk Purchase**
- `TokenBanner.lua:173-180` iterates the filtered real indices with the real API (and the Classic helper), which removes the double mapping behind the Classic gold total.
- Bulk Purchase gets the real index from the slot's `GetID()` as before; `BulkPurchaseMixin.lua:13-29` uses the Classic helper; its fallback (`:137-138`) runs only when the slot's `OnClick` did not already call Blizzard's handler.

**Plugins and public API**
- The container calls optional plugin methods, in the style of the existing `Load`, `InjectOptions` and `OnEvent`: `OnItemSlotCreated(slot)` and `OnItemSlotUpdated(slot, index)` per slot, `OnItemSlotsUpdated()` after a draw. Any addon that registers through `KrowiEVU.PluginsApi:RegisterPlugin` can use them. They are public API: a comment block at the top of `Api/PluginsApi.lua` documents the three methods, their arguments and when they are called (a slot is a `KrowiEVU_MerchantItem<N>` frame with Blizzard's `MerchantItemTemplate` children; `index` is the vendor's real index, as `slot.ItemButton:GetID()` returns), and their signatures stay stable.
- CanIMogIt (`Plugins/CanIMogIt.lua`): when `CIMI_AddToFrame` and `MerchantFrame_CIMIUpdateIcon` exist, `OnItemSlotCreated` calls `CIMI_AddToFrame(slot.ItemButton, MerchantFrame_CIMIUpdateIcon)` (`CanIMogIt/Overlay/overlay.lua:68-95`), and `OnItemSlotUpdated` calls `MerchantFrame_CIMIUpdateIcon(slot.ItemButton.CanIMogItOverlay)`, which reads the item button's `link` (`Overlay/Merchant.lua:12-26`) that drawing sets as Blizzard does. CanIMogIt keeps handling Blizzard's buttons for the buyback tab itself.
- ElvUI (`Plugins/ElvUI.lua`): `OnItemSlotCreated` runs today's modern or classic slot skin on the new slot; `Load` skins the addon's page buttons the way ElvUI skins Blizzard's (Mainline `Merchant.lua:166-169`, Mists `:69-75`); `OnItemSlotUpdated` places money and currency like ElvUI's Retail hook (Mainline `:39-56`) and, on the Classic clients, colours name and border by quality like ElvUI's hook (Mists `:128-153`), for every slot. The `PointXY` no-ops go: ElvUI's `MerchantItemPoint` then moves only Blizzard's hidden merchant-tab buttons, and the buyback post-hook places them again.
- `KrowiEVU_MerchantItemsContainer` (`Api/Api.lua:8`) stays, with `HideAll()`.

**Phase 2 plugins** (`Plugins/GW2_UI.lua`, `Plugins/EllesmereUI.lua`, listed in `Plugins/Files.xml`, each with an entry on the Plugins options page like ElvUI's)
- GW2_UI: active when `GW2_ADDON` exists and `GW2_ADDON.settings.skins.merchant.enabled` is on. `OnItemSlotCreated` applies to the slot the same steps GW2_UI's `SkinMerchantFrameItemButton` applies to `MerchantItemN` (`GW2_UI/Games/Shared/Immersive/Skins/merchant.lua:25-44`): `GwStripTextures`, `GwCreateBackdrop` with `GW2_ADDON.BackdropTemplates.DefaultWithSmallBorder`, `GwStyleButton`, the icon crop, GW2_UI's item border texture, `GW2_ADDON.HandleIcon` and `GW2_ADDON.HandleIconBorder`. That function takes a slot number and looks up `_G["MerchantItem"..index]`, so it cannot be called on the addon's slots directly. `OnItemSlotUpdated` places money and currency like GW2_UI's `PlacePrices` (`:52`) and, on Mists, colours by quality like its `ColorByQuality` and `ColorItemsByQuality` (`:87-109`). Line numbers are from GW2_UI 12.1.0-c264b9d, installed on Retail. The plugin uses only GW2_UI's exposed helpers.
- EllesmereUI: active when `EllesmereUI` exists. Tile look when `EllesmereUI.GetBlizzWindowStyle('merchant')` is not `'off'` and `EllesmereUIDB.merchantShowAsList` is off: EllesmereUI's tile skin is built from its private skin engine (`ns.WSkin` in `EllesmereUIBlizzardSkin_WindowEngine.lua:34-35`; `SkinMerchantTile` in `EllesmereUIBlizzardSkin_WindowPacks.lua:7796`), which no other addon can call, so the plugin draws the tile itself with its own code: fill `0.08, 0.08, 0.08, 0.92` (`WindowEngine.lua:71`), border through EllesmereUI's public `ApplyBorderStyle`, the slot art faded with `SetAlpha(0)` on the addon's own frame, the square rarity border, the icon re-anchored `LEFT`, names with `SetMaxLines(2)`. Item levels when `EllesmereUIDB.merchantShowItemLevel` is on: the plugin's own code with EllesmereUI's public `GetFontPath`, `SlugFlag` and `GetItemLevelColor`, as EllesmereUI's overlay does (`WindowPacks.lua:8027-8085`), redrawn by `OnItemSlotUpdated` and by a post-hook on `EllesmereUI._Merchant_RefreshItemLevels`.
- EllesmereUI's license reserves all rights, so its plugin contains no EllesmereUI code: it calls EllesmereUI's public functions and draws the rest itself. GW2_UI ships no license file; its plugin only calls GW2_UI's own functions.

**Removed**: `Gui/MerchantFrame.lua:132-268` (every API wrapper, the alternate-currency index hook, the popup replacements); `Gui/MerchantItemsContainer.lua:17-56` and the `MERCHANT_ITEMS_PER_PAGE` write at `:91`, the `MerchantItem13+` frames and `:110-120`; `Krowi_ExtendedVendorUI.lua:45-51`; `Filters.lua:105-114`; the `MerchantFrame_Update()` call at `OptionsButtonMixin.lua:11` (it redraws the grid instead); the `MerchantFrame_SetFilter` entry in `.vscode/settings.json`.

## Options considered
1. **Own slots on Blizzard's item template and click code (recommended).** Meets every requirement; the work is the drawing copy, the paging and the plugin hooks.
2. **Own slots with an own click path and own popups.** Fully separate from Blizzard's merchant functions, but the bag and character-slot drop handlers would no longer see `MerchantFrame.extendedCost` or `highPrice`, so a dragged token or expensive item would be bought without confirmation (fails 5), and the popups would drift from Blizzard's rules. Not chosen.
3. **Refill Blizzard's own `MerchantItemN` after each refresh.** Keeps third-party decorations on those buttons, but writes fields onto Blizzard frames (fails 13), has to redo itself after every partial Blizzard refresh (quality on `GET_ITEM_INFO_RECEIVED`), and addons that work out the index from `MerchantFrame.page` would mark the wrong item. Not chosen.
4. **Keep the API replacement and fix the smaller findings one by one.** Smallest change and nothing moves for any player; other addons keep seeing the filter (fails 15) and the API-move risk stays. The fallback if this redesign is not wanted.

## Areas of concern
- **Taint and secret values.** After the change, the only addon code on Blizzard's paths is post-hooks (`MerchantFrame_UpdateMerchantInfo`, `MerchantFrame_UpdateBuybackInfo`, `MerchantFrame_UpdateRepairButtons`, `MerchantFrame_Update` for the token banner, `ResetSetMerchantFilter`, `MerchantFrame` `OnShow`, `OnHide`, `OnMouseWheel`), plus method calls on Blizzard frames (`Hide`, `Show`, `SetPoint`, `SetSize`). What stays tainted: a click on an addon slot runs Blizzard's click code reading fields the addon set on its own button (`price`, `extendedCost`, `link`), so it writes `MerchantFrame.extendedCost`, `highPrice`, `itemIndex` and `count` from tainted code. 22.2 does the same, nothing protected is on that path, and option 2 would remove it only by giving up the confirmations. `KEVU_BULK_CONFIRM` stays an addon-owned `StaticPopupDialogs` entry, as today. No new secret-value reads; `SearchBoxMixin.lua:49-65` (`UnitName('npc')`) is untouched and stays in Known debt. `krowi:taint-reviewer` runs on the diff, Classic branches included.
- **Clients.** Retail draws with the Mainline copy, quality colours and the quest icon; Mists, Anniversary and Era share the Classic copy (no `C_MerchantFrame.GetItemInfo`, heirlooms from Wrath on, page text `PAGE_NUMBER`, alternate-currency offsets 2/31 and -12 instead of 0/31 and -14). The filter menu's Retail-only entries are unchanged. All four are checked in game.
- **Blizzard API changes.** None needed now. The design depends on `MerchantItemTemplate`, `MerchantItemButton_OnClick`, `MerchantItemButton_OnModifiedClick`, `MerchantItemButton_OnEnter`, the four refresh functions it hooks, `AltCurrencyFrame_Update`, the `MoneyFrame_*` and `SetItemButton*` helpers and `CurrencyContainerUtil`. When Blizzard changes its per-item block, the drawing copy needs the same change. `Find-DeprecatedApi.ps1` runs for `live`, `classic`, `classic_anniversary` and `classic_era`.
- **Other addons, plugins and skins.** Better: Auctionator's tooltip prices and vendor price cache, Zygor's auto-buy, TSM's vendor buy tab, Simulationcraft's `/simc merchant`, Wowhead_Looter on Classic (with no `GetMerchantFilter` there it no longer resets and restores Extended Vendor UI's filter, and it scans the whole vendor), AllTheThings' debug window, Pawn's compare slot; EllesmereUI's bulk buy and Extended Vendor UI's Bulk Purchase no longer both open on one shift-click. Unchanged: Pawn's and Zygor's tooltips, TSM's `BuyMerchantItem` hook (now with the real index), Krowi_Vendorer. Drawn on Blizzard's now-hidden `MerchantItemN` and served by the phase 2 plugins: GW2_UI's skin, EllesmereUI's tile skin and item levels (requirements 18-20). Both plugins depend on those addons' current names (`GW2_ADDON` helpers and settings, `EllesmereUI.GetBlizzWindowStyle`, the `EllesmereUIDB` keys), and EllesmereUI's tile is redrawn by Extended Vendor UI, so it does not follow later EllesmereUI design changes by itself. Not served yet: Plumber's merchant prices (see Phases). Any of these authors can also use the public plugin methods. Conflicting in both designs: EllesmereUI's list mode, TSM's vendoring window, Plumber's token display (it hides `MerchantMoneyInset`, the token banner's parent), GW2_UI's extended vendor on Mists. CanIMogIt and ElvUI: requirements 16 and 17.
