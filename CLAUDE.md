# CLAUDE.md

Krowi's Extended Vendor UI (prefix `KrowiEVU`, acronym `KEVU`) is a World of Warcraft addon in Lua 5.1 + WoW XML that turns Blizzard's merchant frame into a grid of configurable rows and columns and adds custom filters (pets, mounts, toys, appearances, sets, illusions, recipes, housing, armor and weapon types), a search box, a token banner with total costs, and a bulk purchase window. The workspace-wide rules (tooling traps, the game loop, taint, git, release safety, how Krowi wants choices presented) load from `../CLAUDE.md` and `Krowi_ClaudeKit/WowAddons.md`; this file adds only what is specific to this repo.

There is no build, lint or test step: the game is the test harness. The `krowi` plugin (enabled in `.claude/settings.json`) syntax-checks every edited `.lua` with Lua 5.1 and guards the known tooling traps. The repo is public and takes outside pull requests, but `.claude/settings.json` points at the private kit by absolute path, so the plugin loads only on Krowi's machine; that is intended.

## Clients and loading

- One TOC, `Krowi_ExtendedVendorUI.toc`, for four clients: `## Interface` (line 1) holds one number each for Retail 12.x, Mists Classic 5.5.x, TBC Anniversary 2.5.x and Classic Era 1.15.x. There are no per-client TOCs or TOC conditionals; code branches at runtime on `addon.Util.IsMainline` (`WOW_PROJECT_ID == WOW_PROJECT_MAINLINE`, `Libs/Krowi_Util/Krowi_Util.lua:24`), so every Classic client takes the same path. The Pets, Sets, Illusions, Recipes and Housing filters are Retail-only.
- Saved variables `KrowiEVU_Options, KrowiEVU_Filters, KrowiEVU_Debug`, all account-wide (TOC line 8; `KrowiEVU_Debug` is never used). A new saved variable must be added to that line or it is lost on logout.
- `## LoadWith: Blizzard_MerchantFrame` does nothing: no client has that addon. `MerchantFrame` comes from `Blizzard_UIPanels_Game`, which loads before any addon, and the files rely on that at load time (`MerchantItem1:GetSize()` at `Gui/MerchantItemsContainer.lua:17`, the page controls in `Gui/Paging/Paging.lua`).
- Load order is the TOC: `Libs\Files.xml` (Krowi_Util, LibDBIcon, the Ace libs, Krowi_PopupDialog, Krowi_Menu, Krowi_Currency, Krowi_Util's `Options/InjectOptions.lua`, then `Libs.lua`), `Api\Files.xml`, `Plugins\Files.xml`, `Localization\Files.xml`, `Krowi_ExtendedVendorUI.lua`, `Options\Files.xml` (starting with Krowi_Util's `Options/Options.lua`), `Libs\Krowi_Util\Icon.lua`, `Icon.lua`, `Filters.lua`, `Gui\Files.xml`. A file only sees what earlier files defined, and a new `.lua` must be listed in its folder's `Files.xml` or it never loads. Most of the merchant-frame work (hooks, the page controls) runs when its file loads, not at boot; the item slots are created at boot.
- Boot is a single `ADDON_LOADED` for this addon (`Krowi_ExtendedVendorUI.lua:14-42`): plugin options, `addon.Options:Load(true)` (AceDB `KrowiEVU_Options`, then each options page; the Profiles page calls `addon.Filters:Load()`, which creates AceDB `KrowiEVU_Filters`), plugins, `MerchantItemsContainer:LoadMaxNumItemSlots()`, the filter button, search box, options button, token banner, icon and bulk purchase, `addon.Api.Load()`, and on Retail `C_HousingCatalog.CreateCatalogSearcher()`. No other event is registered; merchant open and close are followed through hooks.

## Libraries

- Submodules under `Libs/`: `Krowi_Util`, `Krowi_Menu`, `Krowi_PopupDialog`, `Krowi_Currency` (develop and release them in `../Krowi_Libraries/<lib>`, never here). Bundled, not submodules: AceConfig, AceDB, AceDBOptions, AceGUI, LibDBIcon. LibStub, CallbackHandler, LibDataBroker and AceLocale come from Krowi_Util. The repo defines no LibStub library of its own.
- `Libs/Libs.lua` calls `KROWI_LIBMAN:NewAddon(...)`, which sets `addon.Util` (Krowi_Util_2), `addon.MenuBuilder` (Krowi_Menu_2), `addon.Metadata` (TOC fields) and `addon.Localization`, then sets `addon.CurrencyLib` (Krowi_Currency_2). Krowi_Util files loaded into this addon's namespace set `addon.InjectOptions`, `addon.Options` and `addon.Icon` (with the addon compartment globals). Krowi_Util's `Options/Profiles.lua` is not loaded; this repo's `Options/Profiles.lua` takes its place.

## Architecture

- **The merchant tab shows the addon's own item slots** (`Gui/MerchantItemsContainer.lua`). Slots `KrowiEVU_MerchantItem<N>` are created from Blizzard's `MerchantItemTemplate` up to `NumRows * NumColumns`, so clicks, dragging, stack splitting, tooltips, cursors and Blizzard's purchase confirmations run Blizzard's own handlers with the vendor's real index (`ItemButton:SetID`). Only `OnClick` is the addon's (`ItemButton_OnClick`), so Bulk Purchase can take the modified clicks. `merchantItemsContainer:Update()` rebuilds the filtered list (`addon.Filters:BuildList`), places and draws the page and calls the plugin methods; it runs from the `MerchantFrame_UpdateMerchantInfo` post-hook (merchant tab only), on filter and page changes, on `MERCHANT_SHOW` and, on Retail, when missing item data arrives. Blizzard's merchant code runs untouched underneath: it fills its own `MerchantItem1-10` and page widgets, which the post-hook hides. The buyback tab uses Blizzard's `MerchantItem1-12`, laid out by the `MerchantFrame_UpdateBuybackInfo` post-hook. Nothing replaces a Blizzard function, constant or popup (see Taint-sensitive areas).
- **Drawing a slot** (`Gui/MerchantItemSlot.lua`) copies Blizzard's per-item code: Mainline mirrors live `MerchantFrame.lua:275-403`; one Classic variant mirrors classic TBC `MerchantFrame.lua:196-321` for Mists, Anniversary and Era; the alternate-currency part copies `MerchantFrame_UpdateAltCurrency`, which only finds `MerchantItemN`. When a patch changes Blizzard's per-item code, change the copy the same way. `merchantItemSlot.GetItemInfo` returns the `C_MerchantFrame.GetItemInfo` table on every client (built from `GetMerchantItemInfo` on Classic); the token banner and Bulk Purchase use it too.
- **Paging** (`Gui/Paging/`): own previous and next buttons (copies of Blizzard's XML) and page text, anchored in `Gui/MerchantFrame.lua`, following Blizzard's paging rules with the filtered count; mouse-wheel paging through a `HookScript` on `MerchantFrame`. `Gui/MerchantFrame.lua` resizes `MerchantFrame` (`SetMerchantFrameSize`) and re-anchors its insets and repair buttons (`UpdateMerchantInfoLayout`).
- **Filters** (`Filters.lua`): custom filter ids `KrowiEVU_LE_LOOT_FILTER_*` (100 and up) next to Blizzard's `LE_LOOT_FILTER_*`. The active filter is the addon's own (`filters:GetFilter`, `SetFilter`, `SyncFilter`, `RegisterListener`); on Retail `SetFilter` also passes the same value to the real `SetMerchantFilter`, custom ids included, and the client-side `Validate` filters what the server returns. Listeners: the grid (page 1, redraw) and the search box. On vendor open, Retail's `ResetSetMerchantFilter` post-hook and Classic's `OnShow` hook (`Gui/FilterButton/FilterButtonMixin.lua`) apply RememberFilter. The filter and options menus are built with `addon.MenuBuilder` (Blizzard's Menu API on Retail, a UIDropDownMenu frame on Classic, both inside Krowi_Menu).
- `Gui/`: `FilterButton/`, `SearchBox/` and `OptionsButton/` (modern and classic variants through local `CreateModern`/`CreateClassic`), `TokenBanner/` (gold, currency and item totals over the filtered list, replacing Blizzard's money and token row), `BulkPurchase/` (a shift-click on an item opens `KrowiEVU_BulkPurchaseFrame`, which buys stack by stack every 0.5 s through `BuyMerchantItem` with the real index).
- `Options/`: AceConfig pages in Blizzard Settings (General, Profiles, Plugins, Credits). Defaults for `KrowiEVU_Options` are in `Options/Defaults.lua`, for `KrowiEVU_Filters` in `Filters.lua:63-103`; both are AceDB with every character on the shared `Default` profile. `filters:SetFilter` also writes a raw `LastFilter` at the root of `KrowiEVU_Filters`. There is no version field and no migration code.
- **Public API** (`Api/`): the global `KrowiEVU` with `PluginsApi` (`RegisterPlugin`, `RegisterEvent`, `LoadPluginLocalization`, `CallPlugins`) and `UtilApi.InjectOptions`. The item slot plugin methods (`OnItemSlotCreated`, `OnFirstDraw`, `OnItemSlotUpdated`, `OnItemSlotsUpdated`) are public and documented at the top of `Api/PluginsApi.lua`: keep their signatures stable. Built-in plugins: `Plugins/CanIMogIt.lua` (attaches CanIMogIt's overlay to the addon's slots and refreshes it on every draw and on CanIMogIt's own `OptionUpdate` and `ResetCache` messages) and `Plugins/ElvUI.lua` (on Classic the addon's own ElvUI slot skin when a slot is created, then on every client the steps of ElvUI v16's one merchant skin, `ElvUI/Game/Shared/Skins/Merchant.lua`, on a slot's first draw, as both ran in 22.2; ElvUI skins at `PLAYER_LOGIN`, so the page controls and the buyback re-layout for ElvUI before v16 wait for `OnFirstDraw`; when ElvUI's merchant skin changes, follow it here). Krowi_Vendorer reads `KrowiEVU_MerchantItemsContainer` (`Api/Api.lua:8`) to step aside and calls its `HideAll()`, which hides the addon's slots and page controls and Blizzard's `MerchantItem1-12`; keep both.

## Taint-sensitive areas

`Gui/MerchantItemsContainer.lua`, `Gui/MerchantItemSlot.lua`, `Gui/Paging/`, `Gui/MerchantFrame.lua`, `Filters.lua` (the server filter), the open hooks in `Gui/FilterButton/` and `Gui/SearchBox/`, `Gui/TokenBanner/`, `Gui/BulkPurchase/` and `Plugins/` hook Blizzard functions and frames or sit on the purchase path. Run the `krowi:taint-reviewer` agent after changing any of them, and check the Classic branch as well as Retail. The rules the design keeps: no Blizzard function, global, constant, `C_*` field or popup is replaced or written; Blizzard frames get only method calls (`Hide`, `Show`, `SetPoint`, `SetSize`) and `hooksecurefunc` or `HookScript` post-hooks; the addon never calls a Blizzard refresh (`MerchantFrame_Update`, `MerchantFrame_UpdateMerchantInfo`); fields are written only on the addon's own frames. What stays tainted: a click on an addon slot runs Blizzard's click code reading fields the addon set on its own button (`price`, `extendedCost`, `link`), so Blizzard writes `MerchantFrame.extendedCost`, `highPrice`, `itemIndex` and `count` from tainted code; nothing protected is on that path. Also tainted, as in 22.2 (taint review of 2026-10-19): the slots' `UpdateTooltip` and `SplitStack` (set by `MerchantItemButton_OnLoad` when addon code creates the slot), so the 0.2 s tooltip refresh while hovering runs tainted; and closing Blizzard's shared `StackSplitFrame` on a page change or tab switch, whose `OnHide` replays held keys with `RunBinding`. Do not give the slots an own click path with own popups: the bag and character-slot drop handlers (live `ContainerFrame.lua:1349-1356`, `PaperDollFrame.lua:1626-1629`) confirm a purchase only when `MerchantItemButton_OnClick` has set `MerchantFrame.extendedCost` or `highPrice`. Until the redesign in `docs/work/2026-10-18-addon-owned-grid/`, the addon filtered by replacing Blizzard's merchant API; that design and its 2026-10-15 review findings are in that work folder.

## Localization

`Localization/enUS.lua`, `deDE`, `frFR`, `itIT`, `ruRU`, `zhCN` and `Shared.lua`, loaded by `Localization/Files.xml`. The `AUTOGENTOKEN` marker is on line 6 of `enUS.lua` and line 7 of the others; above it is only the `NewLocale` call and `KrowiEVU.PluginsApi:LoadPluginLocalization(L)`. A new string goes into `enUS.lua` below the marker (22.0 appended its strings at the end; the next CurseForge export sorts them). Do not add `L["..."] = true` to the other locale files: outside the default locale AceLocale stores the key itself, so the player sees the raw key instead of the English text. Those files hold only translations and fall back to enUS; a renamed key is renamed in every file that has it. Ask Krowi whether a new string should also go onto the CurseForge localization page. `Shared.lua` aliases Blizzard global strings and finally sets `addon.L`.

## Code style

Match the file you are editing; this repo's style is not Krowi_AchievementFilter's and must not be converted to it:

- Indentation is mixed. Tabs in `Filters.lua`, `Gui/MerchantFrame.lua`, `Gui/FilterButton/FilterButtonMixin.lua`, `Gui/OptionsButton/OptionsButtonMixin.lua` and the FilterButton, OptionsButton and SearchBox XML; 4 spaces in the other files. Several files mix both (`Plugins/ElvUI.lua`, `Gui/TokenBanner/TokenMixin.lua`, `Gui/SearchBox/SearchBoxMixin.lua`): follow the surrounding block. New files use 4 spaces, like most recently added code.
- No semicolons (two lines in `TokenMixin.lua` are the exception).
- Single quotes in code; the locale files use double quotes (the CurseForge export format), except `Shared.lua`.
- Line 1 is `local _, addon = ...` (or `local addonName, addon = ...`); older files put `-- [[ Namespaces ]] --` above it. No copyright banner. Section comments are `-- [[ Name ]] --`.
- Module tables on `addon.*` (`addon.Gui.FilterButton`, `addon.Filters`) with a camelCase local alias; functions PascalCase, locals camelCase; globals, frames, mixins and templates `KrowiEVU_<Name>`, `KrowiEVU_<Name>Mixin`, `KrowiEVU_<Name>_Template`.
- CRLF on disk (LF in git, `core.autocrlf=true`), no BOM, no final newline (except `Localization/Files.xml`, which git stores with CRLF, and the bundled Ace libs). There is no `.editorconfig`.
- `.vscode/settings.json` lists the globals the Lua language server accepts (still with `KrowiV_*` names from Krowi_Vendorer). The Ketho WoW API extension writes the `Lua.runtime.*` and `Lua.workspace.library` keys there and prunes WoW API globals itself, so add only addon and library globals by hand.
- Do not restyle lines you are not otherwise changing.

## Testing in game

`.vscode/settings.json` fsdeploys on every save (`deployWorkspaceOnSave`) to `_retail_` only; the Classic, Era and PTR nodes are commented out. Its nodes exclude `.claude` and `docs`, so a save no longer copies a worktree's files into the AddOns folder, but it still redeploys the main checkout over a worktree deploy. Before an in-game check, run the kit's `Deploy.ps1 -WhatIf` (add `-Client Classic`, `Anniversary` or `Era` for the other clients) and deploy, then `/reload` and `Read-GameErrors.ps1` (see `WowAddons.md`, Closing the loop with the game). Open a vendor and switch filters, page, search and buy back; check a Classic client separately, since it runs the non-mainline branches. Buying is a real action: test bulk purchase on cheap items.

## Git and release

- `main` is the only long-lived branch and the release branch. Releases used to be cut on `dev` and merged to `main` through a "Dev" pull request (#84, #86); `dev` was merged into `main` and removed on 2026-10-18. Branch new work from `main` and open PRs against it.
- Release only with the plugin's `krowi:release` skill. Versions are `major.minor` (22.1) and ship as stable, `--stability stable`: no GitHub release has ever been a pre-release.
- `origin` still points at the repo's old name, `TheKrowi/Krowi_MerchantFrameExtended` (GitHub redirects it to `TheKrowi/Krowi_ExtendedVendorUI`); the `StefanoVe` remote is a contributor's fork. Branches `cata-classic-test`, `cata-classic-test-2` and `shopping-list` are old and unmerged; `filters` is merged.
- `raw/` and `wiki/` hold LLM-wiki notes from 2026-06-03 (a codebase analysis and six articles), not a GitHub wiki. They are stale (version 21.3, Cataclysm and Wrath clients, no Bulk Purchase): trust the code over them. Neither fsdeploy nor the addon manager's zip ships them.
