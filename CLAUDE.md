# CLAUDE.md

Krowi's Extended Vendor UI (prefix `KrowiEVU`, acronym `KEVU`) is a World of Warcraft addon in Lua 5.1 + WoW XML that turns Blizzard's merchant frame into a grid of configurable rows and columns and adds custom filters (pets, mounts, toys, appearances, sets, illusions, recipes, housing, armor and weapon types), a search box, a token banner with total costs, and a bulk purchase window. The workspace-wide rules (tooling traps, the game loop, taint, git, release safety, how Krowi wants choices presented) load from `../CLAUDE.md` and `Krowi_ClaudeKit/WowAddons.md`; this file adds only what is specific to this repo.

There is no build or lint step, and the only tests run in the game (`/kevutest`, see Testing in game). The `krowi` plugin (enabled in `.claude/settings.json`) syntax-checks every edited `.lua` with Lua 5.1 and guards the known tooling traps. The repo is public and takes outside pull requests, but `.claude/settings.json` points at the private kit by absolute path, so the plugin loads only on Krowi's machine; that is intended.

## Clients and loading

- One TOC, `Krowi_ExtendedVendorUI.toc`, for five clients: `## Interface` (line 1) holds one number each for Retail 12.x, Mists Classic 5.5.x, TBC Anniversary 2.5.x, WoW Forever 1.60.x (16001, since 2026-10-22) and Classic Era 1.15.x. There are no per-client TOCs or TOC conditionals; code branches at runtime on Krowi_Util's flags (2.8). WoW Forever is project `WOW_PROJECT_CAMELOT` (18) with a 1.x build but runs Retail's interface (Blizzard's camelot game type is in the mainline family, so it loads `Mainline/MerchantFrame.lua`), so `IsMainline` is false and `IsClassicEra` true there. Branches about Blizzard's interface (frames, templates, menus, the merchant filter API, slot drawing, paging) read `addon.Util.IsModern` (`IsMainline or IsForever`); Retail-only content and skins (Housing, Warglaives, EllesmereUI) read `IsMainline`; code that means Classic Era alone tests `IsForever` first (`Gui/BulkPurchase/BulkPurchaseMixin.lua:179`). Every Classic client takes the same path. The Pets, Sets, Illusions and Recipes filters run on Retail and Forever, Housing on Retail only. Decisions and evidence: `docs/work/2026-10-21-forever/`.
- Saved variables `KrowiEVU_Options, KrowiEVU_Filters, KrowiEVU_Debug`, all account-wide (TOC line 9; `KrowiEVU_Debug` holds only `/kevutest`'s last 10 runs, `KrowiEVU_Debug.Tests.Runs`). A new saved variable must be added to that line or it is lost on logout.
- `## LoadWith: Blizzard_MerchantFrame` does nothing: no client has that addon. `MerchantFrame` comes from `Blizzard_UIPanels_Game`, which loads before any addon, and the files rely on that at load time (`MerchantItem1:GetSize()` at `Gui/MerchantItemsContainer.lua:18`, the page controls in `Gui/Paging/Paging.lua`).
- Load order is the TOC: `Libs\Files.xml` (Krowi_Util, LibDBIcon, the Ace libs, Krowi_PopupDialog, Krowi_Menu, Krowi_Currency, Krowi_Util's `Options/InjectOptions.lua`, then `Libs.lua`), `Api\Files.xml`, `Plugins\Files.xml`, `Localization\Files.xml`, `Krowi_ExtendedVendorUI.lua`, `Options\Files.xml` (starting with Krowi_Util's `Options/Options.lua`), `Libs\Krowi_Util\Icon.lua`, `Icon.lua`, `Filters.lua`, `Gui\Files.xml`, `Tests\Files.xml`. A file only sees what earlier files defined, and a new `.lua` must be listed in its folder's `Files.xml` or it never loads. Most of the merchant-frame work (hooks, the page controls) runs when its file loads, not at boot; the item slots are created at boot.
- Boot is a single `ADDON_LOADED` for this addon (`Krowi_ExtendedVendorUI.lua:101-133`): plugin options, `addon.Options:Load(true)` (AceDB `KrowiEVU_Options`, then each options page; the Profiles page calls `addon.Filters:Load()`, which creates AceDB `KrowiEVU_Filters`), plugins, `MerchantItemsContainer:LoadMaxNumItemSlots()`, the filter button, search box, options button, token banner, icon and bulk purchase, `addon.Api.Load()`, and on Retail `C_HousingCatalog.CreateCatalogSearcher()`. Merchant refreshes are followed through hooks; the only events are `MERCHANT_SHOW` and `MERCHANT_CLOSED` (`Gui/MerchantItemsContainer.lua`), `MERCHANT_CLOSED` on Retail and Forever for the recipe record (`Filters.lua`), `GET_ITEM_INFO_RECEIVED` while Retail item quality is missing (`Gui/MerchantItemSlot.lua`), the events plugins register, and `/kevutest`'s own during a run.
- **EllesmereUI's merchant list mode** (Retail, Krowi's decision of 2026-10-21): when it is on, `Krowi_ExtendedVendorUI.lua` sets `addon.NotLoaded` and `addon.NotLoadedText`, registers no boot and only shows a notice on the first vendor window of the session. Every later file with load-time work (`Filters.lua`, all of `Gui/`, `Tests/Tests.lua`) starts with `if addon.NotLoaded then return end`, and `Icon.lua` points the addon compartment entry at the notice; a new such file needs the same line. The TOC's `## OptionalDeps: EllesmereUI, EllesmereUIBlizzardSkin` loads EllesmereUI first so its settings can be read at that point; EllesmereUI switches the mode only with a reload. Known limit (taint review of 2026-10-21): `merchantShowAsList` is account-wide, but whether EllesmereUI skins the merchant window at all is per profile and settled at its `PLAYER_LOGIN`, after this check, so with per-specialization EllesmereUI profiles that differ there the decision follows the profile the last character saved (a stock window with the notice, or the grid over the list, until the next reload). Libraries, the API, plugins, locales and option definitions still load but never run, so Krowi_Vendorer finds no `KrowiEVU_MerchantItemsContainer`.
- **WoW Forever's gamepad interface style** (Krowi's decision of 2026-10-22, after the taint review of that day, see Taint-sensitive areas): when it is on at load (`InputUtil.IsGamepadUIEnabled()`, Options, Gameplay, Gamepad, first checkbox), the addon steps aside the same way (`addon.NotLoaded = 'ForeverGamepad'`) and Blizzard's own vendor window stays; the first vendor of the session prints a chat line instead of the notice window, which a gamepad player might not be able to close. The style changes without a reload: switched on after load, the grid stays and the next vendor prints a line saying to `/reload`. `/kevutest` does not exist while the addon is not loaded.

## Libraries

- Submodules under `Libs/`: `Krowi_Util`, `Krowi_Menu`, `Krowi_PopupDialog`, `Krowi_Currency` (develop and release them in `../Krowi_Libraries/<lib>`, never here). Bundled, not submodules: AceConfig, AceDB, AceDBOptions, AceGUI, LibDBIcon. LibStub, CallbackHandler, LibDataBroker and AceLocale come from Krowi_Util. The repo defines no LibStub library of its own.
- `Libs/Libs.lua` calls `KROWI_LIBMAN:NewAddon(...)`, which sets `addon.Util` (Krowi_Util_2), `addon.MenuBuilder` (Krowi_Menu_2), `addon.Metadata` (TOC fields) and `addon.Localization`, then sets `addon.CurrencyLib` (Krowi_Currency_2). Krowi_Util files loaded into this addon's namespace set `addon.InjectOptions`, `addon.Options` and `addon.Icon` (with the addon compartment globals). Krowi_Util's `Options/Profiles.lua` is not loaded; this repo's `Options/Profiles.lua` takes its place.

## Architecture

- **The merchant tab shows the addon's own item slots** (`Gui/MerchantItemsContainer.lua`). Slots `KrowiEVU_MerchantItem<N>` are created from Blizzard's `MerchantItemTemplate` up to `NumRows * NumColumns`, so clicks, dragging, stack splitting, tooltips, cursors and Blizzard's purchase confirmations run Blizzard's own handlers with the vendor's real index (`ItemButton:SetID`). Only `OnClick` is the addon's (`ItemButton_OnClick`), so Bulk Purchase can take the modified clicks. `merchantItemsContainer:Update()` rebuilds the filtered list (`addon.Filters:BuildList`), places and draws the page and calls the plugin methods; it runs from the `MerchantFrame_UpdateMerchantInfo` post-hook (merchant tab only), on filter and page changes, on `MERCHANT_SHOW` and, on Retail, when missing item data arrives. Blizzard's merchant code runs untouched underneath: it fills its own `MerchantItem1-10` and page widgets, which the post-hook hides. The buyback tab uses Blizzard's `MerchantItem1-12`, laid out by the `MerchantFrame_UpdateBuybackInfo` post-hook. Nothing replaces a Blizzard function, constant or popup (see Taint-sensitive areas).
- **Drawing a slot** (`Gui/MerchantItemSlot.lua`) copies Blizzard's per-item code: Mainline mirrors live `MerchantFrame.lua:275-403`, which WoW Forever's `Mainline/MerchantFrame.lua` has unchanged (forever 1.60.1); one Classic variant mirrors classic TBC `MerchantFrame.lua:196-321` for Mists, Anniversary and Era; the alternate-currency part copies `MerchantFrame_UpdateAltCurrency`, which only finds `MerchantItemN`. When a patch changes Blizzard's per-item code, change the copy the same way. One deliberate difference: an empty slot, and a new one, has `hasItem = false` where Blizzard sets nil (Blizzard only tests it for truth), because Transmog Loot Helper retries every frame while the first slot's is nil (#101). `merchantItemSlot.GetItemInfo` returns the `C_MerchantFrame.GetItemInfo` table on every client (built from `GetMerchantItemInfo` on Classic); the token banner and Bulk Purchase use it too.
- **Paging** (`Gui/Paging/`): own previous and next buttons (copies of Blizzard's XML) and page text, anchored in `Gui/MerchantFrame.lua`, following Blizzard's paging rules with the filtered count; mouse-wheel paging through a `HookScript` on `MerchantFrame`. `Gui/MerchantFrame.lua` resizes `MerchantFrame` (`SetMerchantFrameSize`) and re-anchors its insets and repair buttons (`UpdateMerchantInfoLayout`).
- **Filters** (`Filters.lua`): custom filter ids `KrowiEVU_LE_LOOT_FILTER_*` (100 and up) next to Blizzard's `LE_LOOT_FILTER_*`. The active filter is the addon's own (`filters:GetFilter`, `SetFilter`, `SyncFilter`, `RegisterListener`); on Retail and Forever `SetFilter` also passes the same value to the real `SetMerchantFilter`, custom ids included, and the client-side `Validate` filters what the server returns; the server treats the custom ids like All (`/kevutest`'s server list check, 2026-10-24, at a vendor with gear for every armor type). `BuildList` also applies the Gear options (`ValidateGear`: only usable, sub-optimal body armor below the best armor proficiency `C_SpellBook.IsSpellKnown` reports, minimum quality; weapons and armor only, every client) and, on Retail and Forever, records per character which recipe items a vendor shows that it knows (`RecordRecipe`, once per item per visit, cleared on `MERCHANT_CLOSED`), account-wide in `KrowiEVU_Filters`'s AceDB `global.KnownRecipes["Name-Realm"]`, which Hide collected, Recipes my other characters know reads. Listeners: the grid (page 1, redraw) and the search box. On vendor open, the `ResetSetMerchantFilter` post-hook (Retail and Forever) and Classic's `OnShow` hook (`Gui/FilterButton/FilterButtonMixin.lua`) apply RememberFilter. The filter and options menus are built with `addon.MenuBuilder` (Blizzard's Menu API on Retail, and on Forever through the builder config `modern = addon.Util.IsModern`, Krowi_Menu 2.2; a UIDropDownMenu frame on Classic; both inside Krowi_Menu).
- `Gui/`: `FilterButton/`, `SearchBox/` and `OptionsButton/` (modern and classic variants through local `CreateModern`/`CreateClassic`), `TokenBanner/` (gold, currency and item totals over the filtered list, keyed by currency or item id, replacing Blizzard's money and token row; pooled tokens are cleared before each use and a cost without data is skipped; the update runs 0.25 s after a request on its own pending flag, not Krowi_Util's `DelayFunction`, whose slot stays taken after an error; options Gold total and Hide currencies you have none of sit at the end of Krowi_Currency's Money and Currency sections), `BulkPurchase/` (a shift-click on an item opens `KrowiEVU_BulkPurchaseFrame`, which buys stack by stack every 0.5 s through `BuyMerchantItem` with the real index).
- `Options/`: AceConfig pages in Blizzard Settings (General, Profiles, Plugins, Credits). Defaults for `KrowiEVU_Options` are in `Options/Defaults.lua`, for `KrowiEVU_Filters` in the `defaults` table at the top of `Filters.lua` (the recipe record in `global` has none: it is created on first use); both are AceDB with every character on the shared `Default` profile. `filters:SetFilter` also writes a raw `LastFilter` at the root of `KrowiEVU_Filters`. There is no version field and no migration code.
- **Public API** (`Api/`): the global `KrowiEVU` with `PluginsApi` (`RegisterPlugin`, `RegisterEvent`, `LoadPluginLocalization`, `CallPlugins`) and `UtilApi.InjectOptions`. The item slot plugin methods (`OnItemSlotCreated`, `OnFirstDraw`, `OnItemSlotUpdated`, `OnItemSlotsUpdated`) are public and documented at the top of `Api/PluginsApi.lua`: keep their signatures stable. Built-in plugins: `Plugins/CanIMogIt.lua` (attaches CanIMogIt's overlay to the addon's slots and refreshes it on every draw and on CanIMogIt's own `OptionUpdate` and `ResetCache` messages), `Plugins/ElvUI.lua` (on Classic the addon's own ElvUI slot skin when a slot is created, then on every client the steps of ElvUI v16's one merchant skin, `ElvUI/Game/Shared/Skins/Merchant.lua`, on a slot's first draw, as both ran in 22.2; ElvUI skins at `PLAYER_LOGIN`, so the page controls and the buyback re-layout for ElvUI before v16 wait for `OnFirstDraw`; when ElvUI's merchant skin changes, follow it here), `Plugins/GW2_UI.lua` (GW2_UI's merchant skin steps through its `GW2_ADDON` helpers), `Plugins/TransmogLootHelper.lua` (from its author's PR #97: calls TLH's public `UpdateOverlay` after each draw; TLH 12.1.5-02 and later draws on `KrowiEVU_MerchantItem<N>` itself, Retail and Forever) and `Plugins/EllesmereUI.lua` (Retail only: EllesmereUI's merchant tile and item levels, drawn by the plugin itself because EllesmereUI's skin engine is private and its code all rights reserved). Plumber's Merchant Price module moves `MerchantMoneyInset`, the token banner's parent, into a hidden frame and reads only Blizzard's `MerchantItemN`; since Plumber 1.9.7 it stays off while this addon is loaded (`C_AddOns.IsAddOnLoaded`, so also when the addon steps aside; Plumber #533), so the notice plugin #100 added in 24.2 was dropped before release (Krowi, 2026-10-29). A skin plugin is built only for the clients the skinned addon's current release supports (Krowi, 2026-10-18). Skins on WoW Forever are not supported yet: `Plugins/ElvUI.lua` and `Plugins/GW2_UI.lua` return at their top there, so the grid stays unskinned (Krowi, 2026-10-21). Krowi_Vendorer reads `KrowiEVU_MerchantItemsContainer` (`Api/Api.lua:8`) to step aside and calls its `HideAll()`, which hides the addon's slots and page controls and Blizzard's `MerchantItem1-12`; keep both.

## Taint-sensitive areas

`Gui/MerchantItemsContainer.lua`, `Gui/MerchantItemSlot.lua`, `Gui/Paging/`, `Gui/MerchantFrame.lua`, `Filters.lua` (the server filter), the open hooks in `Gui/FilterButton/` and `Gui/SearchBox/`, `Gui/TokenBanner/`, `Gui/BulkPurchase/` and `Plugins/` hook Blizzard functions and frames or sit on the purchase path. Run the `krowi:taint-reviewer` agent after changing any of them, and check the Classic branch as well as Retail. The rules the design keeps: no Blizzard function, global, constant, `C_*` field or popup is replaced or written; Blizzard frames get only method calls (`Hide`, `Show`, `SetPoint`, `SetSize`) and `hooksecurefunc` or `HookScript` post-hooks; the addon never calls a Blizzard refresh (`MerchantFrame_Update`, `MerchantFrame_UpdateMerchantInfo`); fields are written only on the addon's own frames. What stays tainted: a click on an addon slot runs Blizzard's click code reading fields the addon set on its own button (`price`, `extendedCost`, `link`), so Blizzard writes `MerchantFrame.extendedCost`, `highPrice`, `itemIndex` and `count` from tainted code; nothing protected is on that path. Also tainted, as in 22.2 (taint review of 2026-10-19): the slots' `UpdateTooltip` and `SplitStack` (set by `MerchantItemButton_OnLoad` when addon code creates the slot), so the 0.2 s tooltip refresh while hovering runs tainted; and closing Blizzard's shared `StackSplitFrame` when a redraw gives its slot another item (page change, page clamp, filter change, also from inside the `MerchantFrame_UpdateMerchantInfo` post-hook on bag or currency updates, so without a click) or on the switch to Buyback, whose `OnHide` replays held keys with `RunBinding`: a movement key held at that moment gets its key-up blocked and blamed on this addon (taint review of 2026-10-21, accepted). Do not give the slots an own click path with own popups: the bag and character-slot drop handlers (live `ContainerFrame.lua:1349-1356`, `PaperDollFrame.lua:1626-1629`) confirm a purchase only when `MerchantItemButton_OnClick` has set `MerchantFrame.extendedCost` or `highPrice`. Until the redesign in `docs/work/2026-10-18-addon-owned-grid/`, the addon filtered by replacing Blizzard's merchant API; that design and its 2026-10-15 review findings are in that work folder.

WoW Forever (taint review of 2026-10-22): with mouse and keyboard it behaves as Retail. Its gamepad interface style is why the addon steps aside there (Clients and loading). Blizzard's gamepad navigation (`Blizzard_GamepadSmartNavigation`) collects every button in the vendor window, the addon's slots too, and reads `buttonContext` (a key value of Forever's `MerchantItemTemplate`, so written by the addon's `CreateFrame`) and `count` on the selected one (forever `SmartNavigation.lua:1688-1690`, `MerchantFrame.lua:1184-1187`), then rebuilds the gamepad bindings tainted: `ADDON_ACTION_BLOCKED` in combat, also after the window closed. After Buyback, `SelectTopLeftButton` (`MerchantFrame.lua:471-474`) can leave Buy on Blizzard's hidden first slot. No value the addon writes can fix it, since that value is tainted too. Accepted known limit: switched to the gamepad style after load, the grid runs that way until the next reload. The post-hook also hides Forever's gamepad page arrows (`MerchantPageTurnIndicatorLeft/Right`, a plain `Hide`), which otherwise page Blizzard's hidden list.

## Localization

`Localization/enUS.lua`, `deDE`, `frFR`, `itIT`, `ruRU`, `zhCN` and `Shared.lua`, loaded by `Localization/Files.xml`. The `AUTOGENTOKEN` marker is on line 6 of `enUS.lua` and line 7 of the others; above it is only the `NewLocale` call and `KrowiEVU.PluginsApi:LoadPluginLocalization(L)`. A new string goes into `enUS.lua` below the marker (22.0 appended its strings at the end; the next CurseForge export sorts them). Do not add `L["..."] = true` to the other locale files: outside the default locale AceLocale stores the key itself, so the player sees the raw key instead of the English text. Those files hold only translations and fall back to enUS; a renamed key is renamed in every file that has it. Ask Krowi whether a new string should also go onto the CurseForge localization page. `Shared.lua` aliases Blizzard global strings and finally sets `addon.L`.

## Code style

Match the file you are editing; this repo's style is not Krowi_AchievementFilter's and must not be converted to it:

- Indentation is mixed. Tabs in `Filters.lua`, `Gui/MerchantFrame.lua`, `Gui/FilterButton/FilterButtonMixin.lua`, `Gui/OptionsButton/OptionsButtonMixin.lua` and the FilterButton, OptionsButton and SearchBox XML; 4 spaces in the other files. Several files mix both (`Plugins/ElvUI.lua`, `Gui/TokenBanner/TokenMixin.lua`, `Gui/SearchBox/SearchBoxMixin.lua`): follow the surrounding block. New files use 4 spaces, like most recently added code.
- No semicolons (two lines in `TokenMixin.lua` are the exception).
- Single quotes in code; the locale files use double quotes (the CurseForge export format), except `Shared.lua`.
- Line 1 is `local _, addon = ...` (or `local addonName, addon = ...`); older files put `-- [[ Namespaces ]] --` above it. No copyright banner. Section comments are `-- [[ Name ]] --`.
- Module tables on `addon.*` (`addon.Gui.FilterButton`, `addon.Filters`) with a camelCase local alias; functions PascalCase, locals camelCase; globals, frames, mixins and templates `KrowiEVU_<Name>`, `KrowiEVU_<Name>Mixin`, `KrowiEVU_<Name>_Template`.
- CRLF on disk (LF in git, `core.autocrlf=true`), no BOM, no final newline (except `Localization/Files.xml`, which git stores with CRLF, and the bundled Ace libs). There is no `.editorconfig`.
- `.vscode/settings.json` lists the globals the Lua language server accepts (still with `KrowiV_*` names from Krowi_Vendorer). The Ketho WoW API extension writes the `Lua.runtime.*` and `Lua.workspace.library` keys there, removes WoW API functions from `Lua.diagnostics.globals` and appends every other known Blizzard global it sees flagged (see `WowAddons.md`, "Extension-grown globals"), so add only addon and library globals by hand. The 737 it had appended by 2026-10-21, many from GW2_UI and EllesmereUI files opened during the skin work, stay on Krowi's word (2026-10-21) and are committed with 23.0.
- Do not restyle lines you are not otherwise changing.

## Testing in game

fsdeploy is uninstalled (2026-10-21): a save in the main checkout's window redeployed `main` over the build under test on Retail and Anniversary. `.vscode/settings.json` still holds its dead nodes. Before an in-game check, run the kit's `Deploy.ps1 -WhatIf` (add `-Client Classic`, `Anniversary`, `Era` or `Forever` for the other clients) and deploy, then `/reload` and `Read-GameErrors.ps1` (see `WowAddons.md`, Closing the loop with the game). Open a vendor and switch filters, page, search and buy back; check a Classic client separately, since it runs the non-mainline branches. Buying is a real action: test bulk purchase on cheap items.

For one pass per client, ask Krowi to type `/kevutest` and open a vendor with more than one page (`Tests/Tests.lua`, shipped like Krowi_AchievementFilter's tests; it starts when the vendor opens, or at once when one is open): it checks the window as it opened (the vendor's first draw when `/kevutest` was typed before opening it), then sets filter All, page 2, a custom filter, a search, a larger grid from the last page and the grid back, the Gear options, and Gold total off with Hide currencies you have none of on, then waits for Krowi to hover an item, click Buyback and click Merchant. Each step is checked from the frames (slots and their items, page controls, Blizzard's hidden slots, the ElvUI, GW2_UI, EllesmereUI, CanIMogIt and Transmog Loot Helper evidence when those are on, the token banner visible and against the costs of the list, the server's item count for the addon's filters against All, and under All Hide collected for placed decor and the recipe record) and screenshotted with the step named in a banner above the window; the filter, search, grid and the Gear and token banner options go back at the end, and the last two steps check Krowi_Util's client flags against what the client's `WOW_PROJECT_ID` should give and list this addon's Lua errors of the session from BugGrabber, also those from before the run. On WoW Forever run it with the gamepad interface off; with it on, check by hand that Blizzard's window and the chat line show. The last 10 runs are kept (`KrowiEVU_Debug.Tests.Runs`), so a series of runs, one per skin addon with a reload between each, is read in one go afterwards. After the next `/reload`, `.claude/tools/Read-GameTests.ps1 -Client <client>` prints every run's checks with each step's screenshot path, to open with the Read tool, and a summary line per run. The routine never clicks or hovers by itself: automating input breaks Blizzard's terms.

## Git and release

- `main` is the only long-lived branch and the release branch. Releases used to be cut on `dev` and merged to `main` through a "Dev" pull request (#84, #86); `dev` was merged into `main` and removed on 2026-10-18. Branch new work from `main` and open PRs against it.
- Release only with the plugin's `krowi:release` skill. Versions are `major.minor` (22.1) and ship as stable, `--stability stable`: no GitHub release has ever been a pre-release.
- `/kevutest` is part of the release (Krowi, 2026-10-21). The preflight runs `.claude/release-gate.ps1`, which needs every client the TOC claims to have this checkout installed and a completed `/kevutest` run of the TOC version without failed checks since the last change to a shipped file, per skin setup. The preflight's library update counts as such a change, so the order is: preflight (libraries), deploy to every client, Krowi runs `/kevutest` on each and `/reload`s, preflight again until READY, then the dry run.
- `origin` still points at the repo's old name, `TheKrowi/Krowi_MerchantFrameExtended` (GitHub redirects it to `TheKrowi/Krowi_ExtendedVendorUI`); the `StefanoVe` remote is a contributor's fork. Branches `cata-classic-test`, `cata-classic-test-2` and `shopping-list` are old and unmerged.
- `raw/` and `wiki/` hold LLM-wiki notes from 2026-06-03 (a codebase analysis and six articles), not a GitHub wiki. They are stale (version 21.3, Cataclysm and Wrath clients, no Bulk Purchase): trust the code over them. Neither `Deploy.ps1` nor the addon manager's zip ships them.
